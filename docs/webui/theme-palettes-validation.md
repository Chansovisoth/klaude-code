# Browser theme palettes

## 2026-10-22 Klaude Expressive update

Settings now calls this category Theme. The sixteen preset names remain, with
full semantic roles generated by locally bundled Google Material Color Utilities
0.4.0. Nine Material variants, custom accents, local image-derived colors, bounded
transparency and a live preview share Discard / Apply changes. Only the image
seed is saved; pixels never leave the browser. Existing appearance-v1 values
migrate without losing density/motion choices. The early bootstrap restores the
complete generated palette before CSS, avoiding first-paint palette shifts.
Current color/contrast evidence supersedes the fixed-hex measurements below:
see `klaude-expressive-reference.md` and `klaude-expressive-validation.md`.

The first eight palettes were implemented and checked 2026-10-20; expanded to
sixteen and checked 2026-10-22.

Settings → Appearance offers **Slate, Lavender, Sage, Peach, Ocean, Rose, Teal,
Amber, Crimson, Coral, Violet, Indigo, Emerald, Lime, Sky and Cocoa**.
Each preset defines coordinated light and
dark primary, secondary, tertiary and surface roles. Slate additionally defines
neutral text and outline roles, giving white/light and charcoal/dark appearances
without a purple tint. System appearance follows the browser's color scheme.

The picker uses four columns on phones and eight when the settings card has
room, with 44px swatches and at least 44×44px selection targets. Preview, Apply,
Discard and cancellation when leaving Settings retain their existing behavior.
The version 1 storage key accepts the original presets and all sixteen; Lavender
remains the default. Saved choices synchronize between tabs on the same origin.

Initial eight-palette validation:

- Real Chrome checked all sixteen light/dark combinations. Primary button,
  primary/secondary/tertiary container and body/muted/link text role pairs had
  contrast ratios of at least **4.86:1** across the checked surfaces. This checks
  those token pairs, rather than claiming a complete accessibility audit.
- Every new palette was previewed and applied through the actual radio controls.
  Saved values survived reload, synchronized with a second tab, and selected the
  corresponding control. Reset and leaving Settings preserved the saved choice;
  old and invalid preference values retained their expected behavior.
- System light/dark emulation switched Slate's surfaces and neutral text roles.
- At 1440×900, 768×900, 390×640 and 320×480, the picker retained four columns/two
  rows without horizontal overflow, clipped swatches or undersized targets.
- `scripts/webui_markdown_smoke.py` passed, including chat streaming, saved
  replies, code reading, message actions and all sixteen palette combinations.
  Both browser checks reported no JavaScript exceptions.
- JavaScript syntax, Ruff for the modified smoke script and `git diff --check`
  passed. This change affects browser assets only; the Python suite and wheel
  builds were not rerun.

Focused diagnostic: `/tmp/klaude-theme-check.py`. Screenshots:
`/tmp/klaude-theme-preview/` and `/tmp/klaude-markdown-preview/`.

## Eight additional palettes

Crimson, Coral, Violet, Indigo, Emerald, Lime, Sky and Cocoa each add complete
light/dark primary, secondary, tertiary and surface roles. Swatches match their
palette's tones. The existing picker, native radio group and versioned device
preferences are extended without dependencies, backend changes or user-default
writes. Existing themes and chat-density settings retain their current behavior.

`/tmp/klaude-more-palettes-check.py` passed all **32 palette/mode combinations**
in an isolated authenticated Chrome profile, with zero browser exceptions. Each
palette was previewed without saving, applied and synchronized to another tab.
The final Cocoa choice survived a real reload; Discard and leaving Settings
restored the saved palette. Legacy/invalid preferences and System color mode
retained their existing behavior.

The checked primary/on-primary, primary/secondary/tertiary container text and
body/muted/link text against each surface have at least **4.80:1** contrast.
This is a check of those role pairs, not a complete accessibility audit. Layout
checks at 1920/1440/768/390/320px found no horizontal overflow or clipped swatches,
with eight columns/two rows when space permits and four columns/four rows on
phones. Targets remain at least 44px. Phone picker and light Emerald captures
were visually inspected.

The existing Settings smoke now derives its expected palette row count from the
actual number of swatches, retaining checks for responsive controls, draft saves,
navigation, chat density and appearance persistence. Both password/bootstrap
hosts passed **162** Settings layout cases, with zero browser exceptions.
The live host served the updated HTML, CSS and JavaScript with HTTP 200; a browser
refresh loads the palettes without a host restart. JavaScript syntax, indicator
bundle consistency, focused Ruff, Python compilation and whitespace checks passed.
Python backend tests and package builds are not needed for this browser-only
palette extension.
