# WebUI usability refinement

## Inspected baseline

- Clean worktree at `e9fe4a6`; plain deferred JavaScript (`app.js`, `library.js`),
  native controls/dialogs/popovers, shared Material 3 Expressive CSS roles.
- Library already separates Uploads/Generated by stored provenance before paging.
  Its 24-item List/Grid/Gallery, derivatives and reviewed artifact actions stay.
- Knowledge, sources and Skills use bounded shared reads and existing review /
  submit / operation receipts. Knowledge totals count library IDs (up to 1,000),
  with separate per-library source/chunk counts; they are not source totals.
- Connections is currently a disabled browser destination with a configured MCP
  count. Memory management is planned under Settings and has no browser service.
  Neither gains simulated controls in this slice.
- The bridge RFC/planning spec contain historical IA and proposed capabilities;
  the current implementation and latest user handoff take precedence.

## Implementation

1. Record baseline desktop/mobile screenshots and navigation geometry.
2. Keep Library's file presentations; remove redundant search submit control,
   debounce existing backend search, distinguish empty/filter/error states, and
   deduplicate explicit refresh while preserving selection, query, sort, view,
   content and practical scroll position on failure.
3. Render Knowledge, sources and Skills as compact, paged rows with existing
   icons/theme roles. Put Skill metadata/deletion in a native details dialog.
   Enable/disable retains exact reviewed writes and confirmed state; pending,
   rejected and unconfirmed operations remain visible and prevent conflicts.
4. Validate narrow navigation; retain frequent destinations and put secondary
   destinations in a labeled native More popover if six labels do not fit.
   Preserve draft/chat execution state and existing URL navigation conventions.
5. Validate 360/390/768/1280px, light/dark and existing palettes, 795 Knowledge
   libraries, long content, empty/loading states, failed refresh/toggles, review
   cancellation, navigation races, keyboard and pointer interactions. Run focused
   regressions, lint/type/syntax checks and packaging appropriate to this change.

## Boundaries and risks

No dependencies, new APIs, backend/storage/permission changes, commit or push.
Keep stale-request/auth generation guards, bounded reads and accepted-worker
ownership. Avoid optimistic success or bypassing confirmation for a switch.
Do not infer live connectivity, indexing state, repository URLs or generated
workspace artifacts from unavailable metadata. Physical-device and full
screen-reader testing must be distinguished from Chrome viewport checks.

## Continuation
